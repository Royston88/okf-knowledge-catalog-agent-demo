Generation Mechanics
Extraction Stage

How the OKF Bundle is Generated

1. Technical Metadata Pull

The engine queries GCP using the scope defined in catalog.yaml.

  • Reads BigQuery information schema to extract column names, modes, and types.
  • Calls Knowledge Catalog APIs to read existing aspects (e.g. schemas, glossary tags).

2. Bundle Compilation

Translates remote configurations into readable local documents.

  • Transforms BQ schemas into structured YAML tables.
  • Saves catalog data as Markdown files (one per BQ table/asset) under bundle/.
  • Generates navigation index listings (index.md) mapping the BQ project structures.

Metadata representation

Inside an OKF Markdown File

Example: table1.md

---
type: dataplex-types.global.bigquery-table
title: Orders Table
resource:
  name: projects/my-proj/datasets/sales/tables/orders
aspects:
  schema:
    fields:
      - name: order_id
        dataType: STRING
x-kcmd:
  # Hidden serialization key to preserve full 
  # Knowledge Catalog aspects for lossless round-trips
  full_entry_payload: { "aspects": {} }
---
# Orders Table Overview
This table stores customer order transaction details.
It is partitioned on event_date.

Anatomy of the File

  • YAML Frontmatter: Holds structured schema details, ancestors, and technical references.
  • Markdown Body: The place where data stewards or AI models write human-friendly definitions.
  • x-kcmd Tag: Preserves additional Knowledge Catalog parameters (e.g. system properties) that are skipped by standard OKF viewers.

Catalog Reconciliation

Pushing Updates Back to Knowledge Catalog

Reconciliation Engine

Ensures modifications sync cleanly without disrupting unchanged metadata.

  • Normalized Comparisons: Reconciles links by normalizing Project IDs/Names, avoiding duplicate connections.
  • Safe Deletes: Removes catalog associations only if they are configured to sync and missing locally.

Reconstruction & Write

Translates the files back into GCP format.

  • Loads OKF layouts from GCS/Local workspace.
  • Extracts core payload from frontmatter and merges it with the x-kcmd hidden parameters.
  • Pushes clean API calls back to Knowledge Catalog.

End-User Experience

Metadata in the Knowledge Catalog UI

🖥️ The Catalog Entry View

How the synced OKF bundle renders in the Google Cloud Console:

  • Rich Overview Tab: The Markdown body is rendered as formatted HTML, displaying long-form documentation, markdown tables, and runbooks directly on the asset page.
  • Schema & Column Descriptions: BigQuery structural descriptions and custom column-level metadata aspects appear alongside BQ native schemas.

🔗 Glossary & Entry Links

Connecting datasets to governance structures:

  • Semantic Linking: Columns with definition links (e.g. definition: customer-id) show up as clickable links to the Business Glossary term in the UI.
  • Governance Navigation: Users browsing the glossary term can easily see all linked tables and columns in a unified lineage graph, enabling powerful data discovery.
